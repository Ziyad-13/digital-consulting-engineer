## 2024-05-23 - N+1 Queries in Streamlit Layout Components
**Learning:** Streamlit's full-page re-rendering model makes N+1 database queries exponentially worse, especially when those queries are used to construct persistent layout components like sidebars, navigation ribbons, or progress bars. Because Streamlit executes the entire script top-to-bottom on every user interaction, an unoptimized `is_complete(phase)` check run in a loop of 7 phases will hammer the database 14-28 times *on every single button click or input change* in the app.
**Action:** When building layout components or navigation in Streamlit that depend on state across multiple entities (like checking the status of all phases), always use batched queries (e.g., `get_all_completed() -> set`) fetched once at the top of the file/component, rather than querying the database repeatedly inside the render loop.
