## 2026-05-24 - [Optimize N+1 DB Query in Streamlit UI Rendering Loop]
**Learning:** I discovered a significant performance bottleneck where the application was repeatedly hitting the SQLite database within O(N) loops. Specifically, in `utils.render_progress_bar` and the sidebar Phase navigation loop in `app.py`, `db.is_phase_marked_complete(project_id, phase_number)` was being evaluated inside `for pn in PHASE_ORDER:`. Given that Streamlit fully reruns the script on each user interaction, these O(N) redundant queries compound and degrade UI responsiveness.
**Action:** When evaluating layout components or iterating through state checks (like lists or phases) in Streamlit, I must proactively search for N+1 query patterns. I should batch database calls into a single query ahead of the loop—such as fetching a `set()` of IDs or statuses (`get_completed_phases`)—which reduces the O(N) query overhead to an O(1) in-memory lookup.
